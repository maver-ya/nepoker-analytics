# Сайт аналитики неПокера

Открыть: `index.html` (двойным кликом) или `python -m http.server --directory site`.

## Структура
- `index.html`, `style.css`, `app.js` — сайт (без внешних библиотек)
- `data/data.js`, `data/data.json` — данные (генерируются)
- `build_data.py` — сборка данных из Excel

## Как добавить турнир
1. Положить таблицу в `2026/<папка турнира>/` и обновить `Данные/Рейтинг ЦИФЕРБЛАТ.xlsx`.
2. Добавить запись в `TOURNAMENTS` в `build_data.py` (папка, столбец итога, базовый бонус, множители трофеев).
3. `python build_data.py` — смотреть замечания в конце вывода.
4. Если один человек записан по-разному — добавить пару в `ALIASES`.

## Финалы 2025 года
Лежат в `finals2025/*.txt` (набраны вручную по картинкам таблиц из чата и по истории сайта результатов). Формат: шапка `ключ=значение`, затем `[stacks]` (имя и стек на строку) и `[places]` (имена по порядку мест). Новые файлы нужно добавить в `F25META` в `build_data.py`.

## Межсезонка
Серии за 2023–2026 берутся из Excel («Архив» и «Межсезонка»), текущая серия — с сайта результатов:
```
python fetch_site.py     # скачивает данные дней, охоту и прирост рейтинга в interseason/current.json
python build_data.py
```

Быстрое обновление без Excel (только межсезонка и рейтинг после неё): `python update_site.py`.
На GitHub то же делает `.github/workflows/update.yml` — раз в сутки в 06:00 UTC и по кнопке «Run workflow» (коммитит `data/` и `interseason/`, если что-то изменилось).

## Проверки данных
После каждой сборки `build_data.py` печатает замечания и кладёт их в `data.json` (`checks`, `checks_summary`): похожие ники (возможные дубли), игроки межсезонки без финалов, совпадение рейтинга с сайтом результатов, турниры без стеков. Всё видно на странице «О данных»; число замечаний — в подвале сайта.

## Разделы сайта
Обзор · Турниры · Игроки (профиль: форма, сильные/слабые стороны, межсезонки, печать в PDF, картинка для шаринга) · Рейтинг (`#rating`, `#rating/Имя`) · Межсезонка · Интересное (`#fun`: номинации, метрики стека, охота) · Ещё: Карта, Сравнение, Зал славы (`#fame`), Отчёт, О данных.
Старые ссылки `#metrics` и `#hunt` перенаправляются в «Интересное».
## Импорт текущих турниров

`update_site.py` хранит импортированные турниры, расписание, результаты дней
и места финала в `data/tournaments.sqlite3`. При первом запуске архив берётся
из `data/data.json`. Последующие запуски читают архив из SQLite. Автообновление
коммитит базу вместе с остальными файлами каталога `data`.

GitHub Pages использует выгрузку `data/data.js`. История из Excel и рейтинг
по-прежнему собираются отдельно. Опубликованные дельты рейтинга нового
турнира пока не импортируются как очки.

Для автоматического закрытия турнира отдельный массив `finalResults` должен
сопровождаться числом опубликованных мест `const finalResultsCount = N;`.
Архивная общая таблица также поддерживается, если она явно разделяет участников
финала и остальных игроков, а финальные места идут подряд с первого. Проблемы
импорта отображаются в разделе «О данных». Предварительная таблица фишек
не считается финальным протоколом.

## История турниров в SQLite

`python history_db.py` переносит исторические финалы из существующего
`data/data.json` в `data/tournaments.sqlite3` без чтения Excel. Повторный импорт
обновляет архив и сохраняет идентификаторы известных игроков. Исключительно
автоматически импортированные турниры остаются в своих таблицах.

Ежедневное обновление читает из SQLite финалы, алиасы, архив межсезонок,
исторические очки за события и исходный счётчик посещаемости. После миграции
`data/data.json` и `data/data.js` можно заново получить из базы и публичного
источника. Опубликованные снимки межсезонок сохраняются по дате начала серии.
В выгрузке очки события лежат в `pts`, а прирост итогового рейтинга в `delta`.
Если потребуется заново собрать исторические данные из Excel, `build_data.py`
обновит архив в базе и выгрузку сайта.

Подтверждённый вариант ника можно добавить командой
`python history_db.py --alias "Старый ник" "Имя игрока в реестре"`.
При следующей сборке он будет доступен в поиске и старых ссылках. Если
алиас объединяет две строки одного дня, финала или две истории рейтинга,
сборка попросит сверить данные вручную.

В SQLite сохраняются изменения входных данных источника. Повторная загрузка
того же снимка не создаёт новую запись. Снимок хранится вместе с замечаниями
импорта, а результаты отборочных дней и финалов ссылаются на ID игроков.

`python history_db.py --ratings` переносит начисления исходной книги
рейтинга в SQLite отдельно от архива финалов. Эту операцию запускают при
обновлении исторической книги. Ежедневный импорт читает очки из базы.

`python history_db.py --rating-replay` загружает закреплённые публичные версии
источника после финала 3‑8 до второго дня 3‑9. Сборка восстанавливает очки
события, когда сходятся исходный рейтинг и опубликованная дельта. Последующие
дни 3‑9 проверяются тем же способом по сохранённым снимкам. Для другого турнира
понадобится подтвердить правила начисления и привязку рейтингового снимка.

Импорт однодневников распознаёт сезонные турниры «Туз Весны», «Туз Лета»,
«Туз Осени» и «Туз Зимы», в том числе во вкладке предыдущего турнира.
Для нового события в источнике нужны точная дата и подтверждённое число
мест (`finalResultsCount` или `previousTournamentResultsCount`). Для уже
известного события можно сверить состав и места с архивом клуба.
